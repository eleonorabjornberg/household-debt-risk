## Architecture
- **Where:** `atlas/` ("Hot Potato"). A Next.js route handler `app/api/ask/route.ts` (Node runtime) and a small client panel. I'll read `node_modules/next/dist/docs/` before writing Next.js code, as `web/AGENTS.md` says.
- **Model loop:** the Anthropic TypeScript SDK, Sonnet 5.5, a manual tool-use loop of at most 4 turns, and the E1 system prompt, adapted to a reader-facing answer that ends with its sources. The key is read from the Vercel environment, and the base URL is passed explicitly. The route fails closed if the key is missing. The key is never logged.
- **Tools:** the household-credit MCP tools (D5) ported to TypeScript over the same tables: `public_share`, `holdings_by_bucket`, `crisis_windows`, `collateral_coverage`, `nyfed_by_type`, `data_coverage` and `check_answerable` (and `lookup_claim` over the register export). The MCP server is Python over stdio, so it cannot run inside the site's serverless functions. To keep the port honest, **parity tests** compare the TypeScript tool outputs with the Python `household_credit_mcp.core` outputs on the same snapshot (fixtures generated by Python).
- **Every answer cites its query:** the response returns the tool calls (name, arguments), the series IDs and the vintage each tool reported. The panel shows them under the answer.
- **Refusing forecasts:** the system prompt, the ported `check_answerable` (forecast, out-of-range, geography, holder × type), and a server-side check that drops any answer giving a number for a question `check_answerable` refuses. The refusal cases are tested offline (no model) and in the paid build test.
- **Limits** (her d6-preview), enforced server-side before any model call:
  - 5 questions per visitor per day, keyed by a salted hash of the client IP plus the UTC day;
  - a $2/day app-wide stop, from each call's logged `usage` × live Sonnet prices, checked before every call and with a worst-case pre-call guard.

  Both need a durable store shared across serverless instances (**open question 1**). Until one is chosen, the limiter sits behind an interface. Its in-memory version is used only in tests, and on Vercel the route refuses to serve (fails closed).
